# schema 规模交叉对比报告

**实验设计**：题目完全相同（同一份标注集），只改变元数据规模；gold SQL 在两种条件下均已逐题验证可执行且结果非空，因此「schema 规模」是唯一的自变量。

## 1. 两种条件的规模

| 条件 | 表数 | 字段数 | 指标数 | 全量 schema 估算 token |
|---|---:|---:|---:|---:|
| 小 schema | 6 | 38 | 3 | 2707 |
| 大 schema | 32 | 190 | 8 | 9717 |
| **放大倍数** | 5.3x | 5.0x | 2.7x | **3.6x** |

> token 为估算值：按「表名+表描述+字段名+字段描述+别名+指标描述」拼接后，汉字按 1.5 token、其余字符按 0.3 token 折算。**两种条件用同一口径计算**，因此倍数只反映元数据本身的膨胀。

## 2. 各策略 EX：小 schema vs 大 schema

| 策略 | 小 schema | 大 schema | 变化 | p 值 |
|---|---:|---:|---:|---:|
| `llm_only` 裸 LLM 全量灌输 | 80.36% | 71.43% | -8.93pt | 0.031 |
| `col_recall` 字段向量召回 | 75.00% | 60.71% | -14.29pt | 0.013 |
| `col_val_recall` 字段+取值召回 | 78.57% | 58.93% | -19.64pt | <0.001 |
| `full_recall` 三路召回全开 | 78.57% | 66.07% | -12.50pt | 0.019 |
| `llm_filter` 三路召回+LLM 精筛 | 85.71% | 62.50% | -23.21pt | <0.001 |
| `full` 完整链路（含纠错） | 83.93% | 62.50% | -21.43pt | 0.001 |

> p 值是对同一批题在两个条件下逐题配对、bootstrap 2000 次重采样得到的双侧检验结果。

## 3. 关键比值：查封链路相对裸 LLM 基线的优势

| 条件 | `llm_only` | `llm_filter` | 差值 |
|---|---:|---:|---:|
| 小 schema | 80.36% | 85.71% | +5.36pt |
| 大 schema | 71.43% | 62.50% | -8.93pt |

## 4. 延迟变化

| 策略 | 小 schema 单题 | 大 schema 单题 | 变化 |
|---|---:|---:|---:|
| `llm_only` | 7.5s | 8.9s | 1.17x |
| `col_recall` | 7.3s | 7.8s | 1.07x |
| `col_val_recall` | 7.1s | 7.9s | 1.11x |
| `full_recall` | 10.0s | 10.6s | 1.05x |
| `llm_filter` | 10.8s | 11.4s | 1.06x |
| `full` | 10.6s | 11.3s | 1.06x |

## 5. 假设检验

- **假设 1 成立**：schema 扩张后全量灌输基线明显退化，80.36% → 71.43%（-8.93pt）。上下文膨胀使模型难以在海量字段中定位正确的表与口径。
- **假设 2 反向成立（本轮最重要的发现）**：精筛的边际收益随 schema 扩张**反转**。小 schema 下精筛带来 +7.14pt，大 schema 下反而 -3.57pt，相对优势变化 -10.71pt。原因是精筛建立在召回结果之上：schema 变大后召回命中的无关表显著增多，精筛把噪声误判为相关的概率上升，出现「越筛越错」，噪声放大效应超过了它带来的聚焦收益。
- 取值召回增益（小 schema）：+3.57pt
- 取值召回增益（大 schema）：-1.79pt
- 裸 LLM 基线的单题延迟随 schema 膨胀 1.17x（7.5s → 8.9s）。
- 最优策略发生转移：小 schema 下是 `llm_filter`（85.71%），大 schema 下是 `llm_only`（71.43%）。说明**不存在放之四海而皆准的最优链路**，取舍取决于数仓规模。
